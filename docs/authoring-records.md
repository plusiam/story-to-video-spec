# 원문·분석과 시리즈·회차 기록

## 범위

M2 운영 브랜치에 작가 작업 화면을 추가한다. 이미지·영상·음성 생성, API 키 입력, 결제, 렌더, 게시 자동화는 포함하지 않는다. 기존 프로젝트 schemaVersion 1.1은 유지하고 선택형 `authoring.version=1.0` 확장을 둔다. 이전 1.0/1.1 백업 경로와 기존 handoff 1.0 기본 필드는 유지한다.

## 원문·분석 `/p/:id/source`

1. PDF 파일은 브라우저 PDF.js worker가 읽는다. 원본 바이트는 별도 IndexedDB에 보관하고, 추출 페이지·검토 본문·파일 SHA-256·개정 정보는 프로젝트의 authoring.material에 보관한다.
2. 원본 페이지를 미리보기하고 추출 순서·머리말·줄바꿈·누락을 사람이 확인한다. 다단·표 읽기 순서를 자동 교정하거나 OCR하지 않는다. 원본은 직접 다운로드할 수 있다.
3. 검토 본문 수정 시 대조 확인과 이전 분석은 해제된다. 원본 PDF와 제작 원고는 자동 수정하지 않는다.
4. 사람 대조 확인 뒤 외부 AI용 요청문을 복사할 수 있다. 자동 API 전송은 없다. 요청문에는 비공개 본문이 있으므로 외부 전송 범위를 작가가 확인한다.
5. 분석 JSON은 centralChange, segments, findings, characters, locations, questions만 받는다. 승인·진행·출처 결합 키를 거부한다. 원문 서술·인물 주장·회상·해석·제안을 구분하며 근거 인용을 해당 원본 추출 페이지와 공백을 무시하고 대조한다. source ID·개정·해시는 현재 자료에 앱이 결합한다. 오류면 기존 분석이 유지된다.
6. 분석 구간 수는 강제하지 않는다. 기존 제작 뼈대가 4칸인 관계로 정확히 4구간일 때만 별도 명시 버튼으로 반영한다. 그 밖의 분석을 억지로 4구간으로 바꾸지 않는다. 인물·장소 후보는 복사할 수 있지만 얼굴·외모 카드를 자동 생성하지 않는다.
7. 검토 본문을 제작 원고에 복사하는 동작은 별도 버튼이며 기존 원고가 있으면 교체 확인이 필요하다.

원문 낭독은 권리 근거와 사람 확인을 요구한다. 검토한 원문과 제작 원고의 글자가 같아야 한다(공백 차이는 무시). 분량·긴 문장·영어·숫자는 원문을 고쳐야 하는 실패 기준이 아니라 낭독 참고다. 원문 모드의 목표 분은 양수이며 기존 15분 상한을 적용하지 않는다. 각색·창작 기본 검사는 유지한다. 원문·연재의 4칸 요약은 선택이다.

PDF를 보유했다는 사실은 공개·각색·음원 이용 허락이 아니다. 권리 확인은 사람이 한다. 원본 PDF 바이트는 프로젝트 JSON과 시리즈 ZIP에 자동 포함되지 않으므로 별도로 보관해야 한다. 프로젝트 백업에는 추출·검토 텍스트가 포함되므로 비공개로 다룬다. 다른 브라우저에서 원본 보기에는 PDF 재첨부가 필요하다.

## 시리즈·회차 `/p/:id/serial`

- 작업 노트는 제안이다. 대화 결과를 summary/events/characterStates/knowledgeStates/openThreads/visualContinuity/nextEpisode/changeReason 문자열 JSON으로 한 번에 넣거나 직접 편집한다. 승인·회차 번호·진행 키가 섞이면 기존 노트를 유지하고 전체를 거부한다. 사건, 인물 상태, 인물이 아는 사실, 열린 질문, 그림 상태, 다음 회 메모, 수정 이유를 적는다.
- 기존 상태를 읽는 행위만으로 새 노트를 덮어쓰지 않는다. 이전 현재 상태를 빈 칸에만 복사하는 별도 버튼이 있다. 누적 현재 상태는 이번 확정의 메모로 대체되므로, 이전의 유지할 설정과 미해결 질문까지 포함했는지 비교 화면에서 확인한다.
- 원고·기록·현재 상태 변경안을 미리보기한 뒤 확정자와 사람 확인 체크를 요구한다. 편집하면 미리보기와 체크를 해제한다. 저장이 진행 중이거나 실패한 프로젝트는 확정하지 않는다.
- 확정 원고·기록은 새 revision으로 남기고 기존 파일을 덮어쓰지 않는다. 과거 회차를 수정하면 이후 회차를 재검토 표시한다. 최신 회차의 끝 상태는 이전 회차 편집 때문에 과거 상태로 돌아가지 않는다.
- 기록에는 확정 당시 말투·화풍·음성·길이 설정과 인물/장소 카드 사본을 보관한다. 다음 회는 이 스냅샷을 사용하고, 무관한 현재 프로젝트 설정을 섞지 않는다. 스냅샷이 없는 옛 기록은 기본값 확인 필요를 표시한다.
- 다음 회 프로젝트는 새 원고·새 권리 확인·빈 완료 기록으로 시작한다. 이미지 참조 승인은 초기화한다. 재검토할 이전 회차가 남으면 다음 회 생성은 멈춘다.

### 폴더 저장

사람이 선택하고 허용한 작업 폴더만 사용한다. 새 기록은 `작품/{시리즈ID}/회차/{회차ID}/rev-N/원고.md`와 `회차_기록.json`으로 쓴다. 이전 정상 상태는 `상태_이전/시리즈_현재상태.rev-N.json`, 최신 포인터는 `시리즈_현재상태.json`이다. 시작 안내는 특정 고아 revision을 최신이라고 가리키지 않고 상태 파일을 읽도록 한다.

회차 파일을 쓰고 읽어 검증한 뒤 최신 상태를 마지막에 갱신한다. 폴더가 비었거나 정확히 알려진 과거 상태라면 로컬 이력을 재생하여 동기화한다. 다른 계보·더 앞선 폴더는 자동 덮어쓰지 않는다. 실패 시 pending 안내와 재시도를 제공하고, 별도의 확인을 거쳐 미완료 요청만 취소할 수 있다. 취소는 폴더의 기존 파일을 삭제하지 않는다.

브라우저의 프로젝트 변경과 시리즈 변경은 비교 저장·동일 출처 잠금으로 보호한다. 파일 시스템은 여러 기기 사이의 완전한 트랜잭션을 제공하지 않으므로 전후 재검증을 하며 무결성을 무조건 보장하지 않는다. 한 시리즈를 여러 기기에서 동시에 편집하지 않는다.

### 백업·복구

- **회차 묶음 ZIP:** 이번 회차 판본과 상태 연결 자료다. 전체 시리즈 백업이 아니다.
- **전체 시리즈 ZIP:** 이 브라우저에 보관된 상태 이력과 모든 확정 회차 판본, 시작 안내, SHA-256 목록을 포함한다. 새 브라우저에서 전체 ZIP 가져오기로 복원한다. 경로·CRC·SHA·계보와 원고를 검증한 뒤 빈 ID 또는 동일 상태에만 추가하며 다른 상태를 덮어쓰지 않는다.
- **상태 JSON만 가져오기:** 회차 본문이 자동으로 생기지 않는다. 실제 폴더 기록이나 전체 ZIP이 추가로 필요하다.
- **폴더의 앞선 상태로 복구:** 같은 계보의 앞선 판본만 명시 확인 후 브라우저에 복구한다. 갈라진 이력을 자동 병합하지 않는다.
- 폴더 미연결 시 브라우저 보관이라고 표시하며 폴더 저장 완료라고 하지 않는다. 브라우저 데이터 삭제 전에 전체 ZIP과 원본 PDF를 별도 보관한다.

## 오디오 `/p/:id/audio` (오디오 우선 제작)

이 도구의 제작 순서는 원고 확정 → 성우·내레이션 → 효과음·음악과 오디오 마스터 → 필요한 그림만 → 영상이다. 오디오는 화면 없이 들어도 인물·시간·장소가 이해되도록 먼저 만든다. 앱은 음성을 만들거나 재생하지 않고, 사람이 외부 서비스(예: Genspark)에서 만든 결과의 기록만 남긴다. 모델·목소리·설정은 한 가지로 고정하고 서비스의 자동 모델 선택은 쓰지 않는다.

- **낭독 블록:** 이어서 읽을 장면 범위. 블록 수·길이는 정해 둔 값이 없다. 장면 하나씩 녹음하면 억양이 끊겨 범위로 묶는다. 장소가 바뀌는 곳마다 나눈 시작 제안 버튼이 있다(만든 뒤 자유롭게 수정).
- **낭독문:** 장면표 내레이션을 이 화면에서 고치지 않는다. 블록을 만들 때 범위 글의 해시를 저장하고, 원고·장면표가 바뀌면 「다시 확인」을 표시한다. 다시 맞추면 사람 청취·잠금은 풀린다.
- **상태:** 계획 → 생성됨(파일) → 기계 점검(실측·원문 대조) → 사람 청취 → 잠금. 파일·실측 길이 없이 올릴 수 없고, 사람 청취·잠금은 사람이 직접 고른다(앱·AI가 자동 지정하지 않는다).
- **효과음·음악 큐:** 붙는 장면, 소리 설명, 출처 종류·이름, 이용 조건 메모, 파일. 파일이 있는데 이용 조건 메모가 비면 경고한다. Genspark 웹에서 효과음 생성과 다중 트랙 믹싱은 확인되지 않았다.
- **마스터:** 별도 편집기에서 섞은 파일의 이름·실측 길이·음량 메모·화면 없이 들은 확인 메모. 사람 청취·잠금은 모든 장면이 잠금·최신 블록에 덮여야 선택할 수 있다.
- 데이터는 authoring.audio(선택)에 둔다. scenes·target·progress를 건드리지 않아 0~3단계 완료가 풀리지 않는다. 단계 4·5·6 완료 처리와 handoff 1.0은 바꾸지 않는다. voice.service는 옛 typecast 기록과 genspark·other를 모두 받는다.
- 그림 꾸러미에는 장면마다 「이 장면의 화면」(새 그림 / 기존 그림 유지 / 크롭·느린 이동 / 제목·전환 / 아직 정하지 않음)이 있다. 정하지 않은 장면은 기존처럼 모두 보이고, 필터를 켜면 새 그림이 필요 없는 장면의 컷 카드를 숨긴다.

## 그림 꾸러미 `/p/:id/images` (Genspark)

외부 이미지 서비스 Genspark에 붙여 넣을 컷 카드를 만든다. 앱은 Genspark에 접속·생성·결제하지 않는다. 작가가 직접 붙여 넣고 결과를 고른다.

- **설정 안내:** 모델(참조 이미지 한도·크레딧 배율 표시), 16:9, 자동 프롬프트·자동 스타일 끄기. 2026-10-19 화면 기준이며 바뀔 수 있다. 한도 확인: Nano Banana Pro 14장, GPT Image 2 16장, Flash Lite 4장(공식 도구 페이지). Nano Banana 2.1은 미확인.
- **기준 이미지:** Genspark에는 인물 이름 등록 기능이 없어(에셋 메뉴는 업로드·검색뿐) 매번 같은 이미지를 첨부한다. 인물·장소 카드 이름별로 각도·파일 이름을 적고 작가가 확인한다. 파일·각도를 바꾸면 판본이 오르고 확인이 풀린다. 3단계 카드 외모·장소 설명·화풍이 바뀌어도 확인이 풀린다. 승인된 3단계 기준 시트는 첫 첨부로 함께 쓴다.
- **컷 카드:** [첨부 순서] → 화풍 → 화면 → 인물(“N번 이미지 속 대상과 같은 존재”) → 장소 → 장면 → 표정·몸짓 → 빛·계절 → 구도 → 넣지 말 것. 기준 이미지가 있는 인물은 외모를 글로 다시 쓰지 않는다. 없으면 카드 설명으로 대신하고 경고한다. 장면 감정·내레이션은 작가 참고로만 보여 주고 카드에 넣지 않는다.
- **경고:** 모델 한도 초과, 카드 없는 인물 이름, 빈 화면 설명, 기준 이미지 없음, 표정·몸짓 미입력.
- **결과 기록:** 고른 파일, 모델, 시도 번호, 이유, 기록 당시 첨부 목록. 이후 첨부가 바뀌면 다시 확인 표시. 5단계 완료·게시 승인이 아니다.
- 데이터는 authoring.media(선택)에 둔다. 단계 완료·handoff 1.0·기존 Gemini용 imagePrompt.ts는 바꾸지 않는다. 다음 회 프로젝트로 기준 이미지 목록은 아직 이어지지 않는다.
- 한국어 카드가 실제로 인물을 일관되게 유지하는지는 아직 시험하지 않았다.

## handoff 경계

handoff 1.0에는 PDF 원문·분석·사적인 회차 메모를 자동 추가하지 않는다. 제작 원고는 기존 내보내기 범위대로 포함한다. 원문 낭독의 새 권리 정보는 handoff 1.0에 표현되지 않으므로 해당 모드는 인계 준비를 초안으로 표시한다. 권리 근거는 회차 ZIP의 authoringContext에 보관하고 하류 소비자 계약을 별도로 검증해야 한다. 실제 생성·렌더 파이프라인은 여전히 미검증이며 M3 재개 승인으로 간주하지 않는다.

## 시험

```sh
npm run lint
npm run build
npm run test:unit
npm run test:e2e
```

단위 시험은 브라우저 없이 파서·백업 호환·비교 저장·원문 권리·불변 판본·폴더 실패/재시도·계보 복구·ZIP을 확인한다. UI 시험은 실제 Chromium이 필요하다. 원문 소설이나 개인 자료를 테스트 저장소에 넣지 않고 합성 자료를 사용한다. 지침 파일의 빈 제안 양식은 사이트의 확정 기록 가져오기 형식이 아니며, 사이트가 만든 전체 ZIP을 복구에 사용한다.
