# 옛이야기 영상 공방

옛이야기 한 편을 **시니어용 유튜브 영상 재료 한 묶음**(내레이션 원고, 장면표, 일관된 그림, 내레이션 음성, SRT 자막, 유튜브 설명문)으로 만드는 1인 제작 웹도구입니다.

사람이 쓰든 AI 브라우저 도구(Claude in Chrome)가 쓰든 **같은 화면, 같은 순서로** 끝까지 진행되도록 만들었습니다. 각 단계 화면이 사람에게는 입력 양식이고, AI에게는 작업지시서입니다.

> 학생용 4컷 스토리 학습지(story-worksheet)에서 갈라져 나온 저장소입니다. 학생용 기능은 원래 저장소에 그대로 있습니다.

## 주소

| 주소 | 화면 |
| --- | --- |
| `/projects` | 프로젝트 목록, 새로 만들기, 백업 JSON 불러오기 |
| `/p/:id` | 지금 해야 할 단계로 이동 |
| `/p/:id/step/0` ~ `/p/:id/step/7` | 단계별 작업 화면 |
| `/p/:id/step/2?scene=12` | 장면표의 12번 장면으로 바로 이동 |
| `/p/:id/brief` | 브라우저 AI용 작업 브리핑 (전체 지침 + 진행 상태 + 다음 할 일) |
| `/p/:id/export` | 백업 JSON 및 제작 인계 handoff.json 복사·내려받기 |

## 브라우저 AI로 작업할 때

1. `/p/{프로젝트ID}/brief`를 먼저 열어 읽습니다. 「브리핑 전체 복사」로 한 번에 가져갈 수도 있습니다.
2. 화면 위쪽 쪽빛 띠 **「다음 할 일」** 한 문장만 따라갑니다.
3. 요소는 `data-testid` 이름표로 찾습니다.
4. 「화면 준비 중」 단계에 도착하면 멈추고 운영자에게 알립니다.

### 이름표 규칙 (`src/lib/testid.ts`)

- 단계 안 요소: `s{단계}-{대상}[-{두 자리 번호}][-{항목}]` — 예: `s0-title`, `s5-scene-12-upload`
- 화면 공통 요소: `app-{대상}` — 예: `app-next-action`, `app-nav-step-3`, `app-guide-panel`, `app-save-status`, `app-log`
- 단계 완료 버튼: `s{단계}-complete`, 완료 취소: `s{단계}-reopen`, 잠긴 이유: `app-complete-locked-reason`

이름표는 한 번 정하면 바꾸지 않습니다. 바꿔야 하면 `src/guides/index.ts`의 지침 버전을 올립니다.

## 저장 방식: 브라우저 + 작업 폴더

서버나 로그인 없이 동작합니다.

- **브라우저 저장**: 작업 중인 프로젝트 JSON은 이 브라우저(localStorage)에 2초마다 자동 저장됩니다.
- **작업 폴더**(크롬·엣지): 0단계에서 운영자가 컴퓨터 폴더 하나를 연결하면, 저장할 때마다 아래처럼 함께 씁니다.

```
{작업 폴더}/
└── proj_k3x9a2_은혜 갚은 까치/
    ├── project.json   프로젝트 전체 (다른 기기에서 불러오기용)
    ├── script.txt     1단계 원고
    ├── images/        4~5단계 그림 (M3)
    └── audio/         6단계 음성 (M3)
```

- 편집 프로그램(캡컷·브루)에서 이 폴더를 그대로 엽니다.
- 다른 컴퓨터로 옮길 때는 작업 폴더째 옮기고, 프로젝트 목록의 「작업 폴더」에서 불러옵니다.
- 폴더 선택 창과 권한 허용 창은 브라우저가 띄우는 창이라 **운영자만** 누를 수 있습니다. 크롬이 「방문할 때마다 허용」을 물으면 그것을 고르세요.
- 여러 기기에서 동시에 쓰게 되면 Supabase를 붙입니다. 스키마는 `supabase/migrations/001_projects.sql`에 준비되어 있고, `src/lib/storage.ts`의 `store` 한 줄을 바꿔 연결합니다.

## 원문·분석과 시리즈·회차

프로젝트 머리줄의 **원문·분석**에서 PDF를 브라우저로 읽고 원본과 검토문을 대조합니다. 분석 JSON은 제작 원고와 별도이며 근거 인용·출처 개정을 검사합니다. 원문 낭독과 각색 모드를 구분하고, 원문 모드에는 기존 15분 상한을 강제하지 않습니다.

**시리즈·회차**에서는 제안 노트를 미리보기·사람 확인 후 새 판본으로 보관합니다. 원고·기록·누적 상태는 작업 폴더에 쓰거나 ZIP으로 백업할 수 있습니다. 전체 시리즈 ZIP은 모든 보관 판본과 상태 이력을 복원하며, 회차 ZIP은 한 회차 묶음입니다. 다음 회에는 확정 기록의 스타일·카드를 잇되 원고·권리·완료·이미지 승인은 초기화합니다.

- 원문 화면: /p/:id/source
- 시리즈 화면: /p/:id/serial
- 원본 PDF 바이트는 IndexedDB에만 있으며 다른 브라우저로 자동 옮겨지지 않습니다.
- 프로젝트 백업의 추출 텍스트와 시리즈 ZIP은 비공개 자료입니다.
- 폴더 권한·충돌·미완료 저장은 실제 상태로 표시하고 저장한 척하지 않습니다.
- 이미지·영상·음성 생성 및 렌더 기능은 여전히 보류입니다.

사용 절차와 형식 경계: [docs/authoring-records.md](docs/authoring-records.md)

## Aside 대화와 JSON 일괄 입력

0단계 설정, 1단계 스토리, 2단계 장면표, 3단계 화풍·카드에 대화 결과를 한 번에 반영할 수 있습니다. 수동 입력도 유지합니다. 원고는 JSON뿐 아니라 본문 그대로도 받습니다.

- 작업 폴더는 **선택 사항**입니다. 미연결이면 브라우저 자동 저장과 JSON 백업을 사용합니다.
- 확인란·승인·단계 완료 기록은 단계별 JSON으로 가져오지 않습니다. 사람의 확인이 필요합니다.
- 입력 오류는 기존 내용을 바꾸지 않습니다. 원고·장면·카드 수정은 관련 확인과 이후 완료 표시를 해제합니다.
- 캐릭터와 장소에 외부 제작 도구의 Element 참조 이름을 선택 입력할 수 있습니다.
- **project JSON**은 앱 복원용, **handoff.json**은 제작 담당 인계용입니다. 전문 읽기·복사·내려받기를 지원합니다.
- 인계 파일은 0~3단계의 확인·검사·완료 순서가 맞아야 `ready`입니다. 초안에도 `draft`와 보완 목록이 붙습니다.
- 실제 생성, 음성 측정, 렌더링, 자막 시각은 확정하지 않습니다. Claude Code의 하류 `spec.json` 작업과 별개입니다.

형식과 시험 방법: [docs/aside-handoff.md](docs/aside-handoff.md)

## 외부 AI 도움받기

1~3단계에는 「외부 AI 도움받기」 상자가 있습니다. ① 요청문을 복사해 Claude나 Gemini 새 대화에 붙여 넣고 ② 답 전체를 결과 붙여넣기 칸에 넣으면, 형식을 검사한 뒤 반영합니다. 형식이 틀리면 틀린 곳을 글로 알려 주고 아무것도 바꾸지 않습니다.

## 폴더 구조

```
src/
├── types/project.ts       프로젝트 JSON 스키마 (schemaVersion 1.0)
├── guides/                단계별 AI 작업지침 (7칸 양식, 버전 관리)
├── lib/
│   ├── steps.ts           품질 점검, 단계 상태, 「다음 할 일」 문장
│   ├── storage.ts         저장소 계층 (브라우저 저장)
│   ├── folder.ts          작업 폴더 연결과 파일 쓰기
│   ├── text.ts            문장 나누기, 분량 계산, 장면 자동 나누기
│   ├── aiRequests.ts      외부 AI 요청문과 답 검사
│   ├── imagePrompt.ts     화풍 프리셋, 인물 기준 시트·장면 그림 프롬프트
│   ├── brief.ts           작업 브리핑 글 생성
│   ├── testid.ts          이름표 규칙
│   ├── prompts/           이미지·영상 프롬프트 템플릿 (M2·M3에서 손봄)
│   └── export/            자막·PDF·JSON 내보내기 (M3에서 손봄)
├── hooks/useProject.ts    불러오기, 2초 자동 저장, 작업 기록, 단계 완료
├── components/            화면 틀 (단계 목록, 지침 패널, 다음 할 일 띠, 작업 기록, 점검표)
├── steps/                 단계별 작업 화면
└── pages/                 주소별 화면
```

## 콘텐츠 원칙

- 줄거리만 빌린 전래 민담을 운영자의 문장으로 다시 쓰거나 순수 창작합니다. 시판 그림책의 문장·그림은 쓰지 않습니다.
- 화풍은 특정 스튜디오·작가 이름이 아니라 민화풍, 수묵담채, 그림책 수채화 같은 표현으로 지정합니다.
- 유튜브에 올릴 때 AI 사용을 공개하고, 건강·금융 조언은 넣지 않습니다.
